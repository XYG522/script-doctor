# 🎬 AI 剧本体检报告（Script Doctor）

给电影短片 / 电视剧单集剧本做一次「体检」：上传 txt/pdf/docx 剧本，AI 输出结构化体检报告——
角色出场分布、角色关系、情感曲线、节奏分析、逻辑漏洞与动机问题、商业潜力，以及 **3 条可落笔的修改建议**。

> 面向编剧、制片人、剧本策划的 AI 产品经理作品集 MVP。评分为 AI 参考意见，非行业标准评价。

## 功能

- 深色「放映厅」视觉：深炭底 + 琥珀金强调、衬线标题与自动编号章节、图表统一双色系（琥珀金 + 灰，赤陶仅作问题语义色），全界面文案书面化无 emoji；滚动入场动效（淡入上滑）、按钮悬停缩放与卡片浮起等微交互
- 上传 **txt / pdf / docx**（或直接粘贴文本），自动识别 UTF-8 / GBK 编码
- 3 轮 8 次 LLM 调用：解析 → 并行 6 模块 → 综合评分与建议（`deepseek-v4-pro`，json_object 模式）
- 报告页：评分卡、**5 维评分雷达图**、诊断摘要速览、角色出场分布柱状图、情感曲线（**主角/反派/配角最多 3 条线**）、节奏张力图、**角色关系网络图**（力导向布局，节点大小=出场场次，虚线=关系线有问题）、漏洞列表、修改建议
- 防幻觉：引用逐字硬校验、出场场次规则统计、jsonschema 校验 + 自动修复重试、置信度锚点
- 规则硬检查（**本地计算、不调 LLM、0 成本**）：对白占比、每场字数与分布、页数↔时长换算（600 字/页 ≈ 1 分钟，全文 <5000 字只出统计、跳过异常判定）
- 模块勾选 + 成本预估：分析前可勾选 6 个 AI 模块（默认全选），按字数实时预估调用次数与费用（闲时价）；**全不勾 = 纯免费硬检查报告（0 次 LLM 调用、无评分）**；未勾选模块在报告页标注「本次未分析该模块」，雷达图只画已勾选维度
- 剧本医生对话：报告页底部追问剧本相关问题（每问 1 次 LLM 调用，先显示单问预估、后按实际用量累计）。上下文 = 剧本全文（≤2 万字，不建向量库）+ 报告摘要 + 最近 10 条对话；回答为结构化 JSON（正文 + 引用 + 置信度），**引用逐字硬校验**（对不上原文的引用剔除并警告），防幻觉与全链路同源
- 用户系统：打开即见登录/注册页，登录后右上角显示用户名；游客可体验离线演示（在线分析需注册）
- 导出 JSON / Markdown 报告
- 离线演示：内置示例剧本《深夜便利店》+ 预计算报告，**无需 API Key 即可演示**
- 长文本分块：>2 万字自动启用「场头概览 → 分块细读（重叠 1 场）→ 汇总合并」
- 改稿前后对比：任选两条历史记录，总分变化 / 5 维雷达图 / 漏洞修复对照（引用锚点规则对齐）/ 上一版建议采纳判定（分析时携带上一版建议）

## 项目结构

```
script-doctor/
├── app.py              # Streamlit 前端：登录/注册 + 上传/分析/报告/历史/对比页面 + 图表 + 导出
├── auth.py             # 用户系统：SQLite + PBKDF2 加盐哈希（注册/登录校验）
├── history.py          # 分析历史：reports 表（与 users.db 同库）+ 保存/查询
├── compare.py          # 改稿对比：漏洞引用锚点对齐（纯规则，不调 LLM）
├── charts.py           # 报告页图表构建：角色关系网络图等（纯函数，可单测）
├── analyzer.py         # 编排器：文本加载/场次切分/分块/校验/防幻觉
├── prompts.py          # Prompt 链模板 + JSON Schema（8 模块）
├── llm.py              # LLM 适配层：DeepSeek V4 Pro（OpenAI 兼容接口）
├── requirements.txt    # 依赖清单
├── demo_script.txt     # 内置示例剧本（离线演示用）
├── demo_report.json    # 预计算示例报告（离线演示用）
└── README.md
```

## 安装

要求 Python 3.10+（建议 3.11）。

```powershell
# 1. 进入项目目录
cd script-doctor

# 2. 创建虚拟环境（可选但推荐）
python -m venv .venv
.venv\Scripts\Activate.ps1

# 3. 安装依赖
pip install -r requirements.txt
```

## 配置 API Key

Key 从环境变量 `DEEPSEEK_API_KEY` 读取，二选一：

```powershell
# 方式 A：当前终端临时设置
$env:DEEPSEEK_API_KEY='sk-你的key'

# 方式 B（推荐）：项目目录下创建 .env 文件
# 内容：DEEPSEEK_API_KEY=sk-你的key
```

可选：`DEEPSEEK_MODEL` 指定模型名，默认 `deepseek-v4-pro`。

## 运行

```powershell
streamlit run app.py
```

浏览器打开 `http://localhost:8501`：

1. 首次打开是**登录/注册页**：注册一个新账号（用户名 + 密码）即自动登录；也可以点「👀 游客体验」直接进入（游客仅可用离线演示）
2. 粘贴/上传剧本，或点「示例剧本」标签
3. 点「开始分析」→ 观察进度（3 轮 8 调用，约 60–120 秒）
4. 查看报告、下载 JSON/Markdown

**没有 API Key 也能演示**：上传页 →「示例剧本」→「📦 一键离线演示报告」，即加载 `demo_report.json` 的完整报告与图表（登录与游客均可用）。

用户数据保存在 `script-doctor/users.db`（SQLite，首次运行自动创建）；登录状态仅在当前浏览器会话内有效，关闭网页后需重新登录。

## 单次成本（粗估，需以实际账单为准）

| 场景 | 估算 |
|---|---|
| 命中前缀缓存（重复分析同一剧本） | ≈ ¥0.4 |
| 未命中缓存（闲时价） | ≈ ¥1.2 |
| 未命中缓存（高峰价） | ≈ ¥2.4 |

按 DeepSeek 官方闲时价粗算（输入 $0.66/M、输出 $1.98/M、缓存命中 $0.022/M）；prompt 中 system+schema+剧本顺序稳定，可触发自动前缀缓存。单次约 3–6 万输入 token。

## 已知限制（面试时如实说明）

- 定位为「电影短片 / 电视剧单集」：≤2 万字内全量在上下文，**不需要 RAG**
- 分块模式（>2 万字）长线跨块逻辑检测能力有限
- PDF 扫描件（无文本层）无法解析，需转 txt
- 情感值、张力值、评分为模型主观判断，仅作创作参考
- 商业潜力模块不做市场数据支撑，置信度上限 0.5
- 剧本医生对话：>2 万字剧本上下文降级为场头概览（引用校验限于概览内原文）；历史报告未存全文不能对话；对话仅存会话内、刷新即失，不写历史库

## 面试演示建议

1. **开场**：粘贴示例剧本（或自带一个 5–10 场的短剧）→ 在线跑一遍，讲解进度条背后的 3 轮 8 调用设计
2. **亮点展开**：指着一处「引用原文」讲防幻觉硬校验；讲出场场次为什么用规则统计而不是问 LLM
3. **兜底**：网络/Key 失效时切「一键离线演示报告」，演示不中断
4. **收尾**：导出 Markdown 报告，说明「3 条建议都落到具体场次+具体动作」的改稿搭档定位
